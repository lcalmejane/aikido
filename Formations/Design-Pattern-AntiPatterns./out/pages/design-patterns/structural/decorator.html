🎨 Decorator Pattern

Ajouter dynamiquement des responsabilités à un objet

🎨 Design Patterns
⭐ Difficulté: Moyenne
⏱️ 25 min
🏗️ Structure

🎯 Définition

Le Decorator est un pattern structurel qui permet d'ajouter dynamiquement de nouvelles responsabilités à un objet en l'enveloppant dans des objets décorateurs. Il offre une alternative flexible à l'héritage pour étendre les fonctionnalités.

❌ Problème Résolu

  • Éviter l'explosion de sous-classes avec l'héritage
  • Ajouter des fonctionnalités à l'exécution
  • Combiner plusieurs extensions de manière flexible
  • Respecter le principe Ouvert/Fermé

✅ Solution Apportée

  • Extension dynamique des fonctionnalités
  • Composition flexible de comportements
  • Réutilisabilité des décorateurs
  • Transparence pour le client
💡 Analogie : Comme habiller une personne avec différents vêtements (t-shirt, pull, veste, manteau) où chaque couche ajoute une fonctionnalité (chaleur, style, protection) sans changer la personne elle-même.

Éléments Clés

  • Component : Interface commune pour objets et décorateurs
  • ConcreteComponent : Objet de base à décorer
  • Decorator : Classe abstraite des décorateurs
  • ConcreteDecorator : Décorateurs ajoutant des fonctionnalités

💡 Point clé : Chaque décorateur ajoute son comportement puis délègue à l'objet qu'il décore, créant une chaîne de responsabilités.

💻 Implémentations

Exemple : Système de Notification Enrichie


// Interface commune
interface Notification {
    send(message: string): string;
    getCost(): number;
}

// Composant de base
class SimpleNotification implements Notification {
    send(message: string): string {
        return `Notification simple: ${message}`;
    }
    
    getCost(): number {
        return 1; // Coût de base
    }
}

// Décorateur de base
abstract class NotificationDecorator implements Notification {
    protected notification: Notification;
    
    constructor(notification: Notification) {
        this.notification = notification;
    }
    
    send(message: string): string {
        return this.notification.send(message);
    }
    
    getCost(): number {
        return this.notification.getCost();
    }
}

// Décorateurs concrets
class EmailDecorator extends NotificationDecorator {
    private emailAddress: string;
    
    constructor(notification: Notification, emailAddress: string) {
        super(notification);
        this.emailAddress = emailAddress;
    }
    
    send(message: string): string {
        const baseResult = super.send(message);
        const emailResult = this.sendEmail(message);
        return `${baseResult}\n${emailResult}`;
    }
    
    getCost(): number {
        return super.getCost() + 2; // Coût email
    }
    
    private sendEmail(message: string): string {
        return `📧 Email envoyé à ${this.emailAddress}: ${message}`;
    }
}

class SMSDecorator extends NotificationDecorator {
    private phoneNumber: string;
    
    constructor(notification: Notification, phoneNumber: string) {
        super(notification);
        this.phoneNumber = phoneNumber;
    }
    
    send(message: string): string {
        const baseResult = super.send(message);
        const smsResult = this.sendSMS(message);
        return `${baseResult}\n${smsResult}`;
    }
    
    getCost(): number {
        return super.getCost() + 5; // Coût SMS
    }
    
    private sendSMS(message: string): string {
        return `📱 SMS envoyé au ${this.phoneNumber}: ${message}`;
    }
}

class EncryptionDecorator extends NotificationDecorator {
    private encryptionKey: string;
    
    constructor(notification: Notification, encryptionKey: string) {
        super(notification);
        this.encryptionKey = encryptionKey;
    }
    
    send(message: string): string {
        const encryptedMessage = this.encrypt(message);
        const result = super.send(encryptedMessage);
        return `🔐 Message chiffré avec clé ${this.encryptionKey}\n${result}`;
    }
    
    getCost(): number {
        return super.getCost() + 3; // Coût chiffrement
    }
    
    private encrypt(message: string): string {
        // Simulation du chiffrement
        return `[ENCRYPTED:${message.split('').reverse().join('')}]`;
    }
}

// Utilisation
console.log("=== Système de Notifications ===");

// Notification simple
let notification: Notification = new SimpleNotification();
console.log(notification.send("Message de test"));
console.log(`Coût: ${notification.getCost()}€\n`);

// Notification multi-canal avec chiffrement
notification = new EncryptionDecorator(
    new SMSDecorator(
        new EmailDecorator(
            new SimpleNotification(),
            "user@example.com"
        ),
        "+33123456789"
    ),
    "AES256_KEY"
);

console.log(notification.send("Message confidentiel"));
console.log(`Coût total: ${notification.getCost()}€`);


<?php

// Interface commune
interface DataSource {
    public function writeData(string $data): void;
    public function readData(): string;
}

// Composant de base
class FileDataSource implements DataSource {
    private string $filename;
    
    public function __construct(string $filename) {
        $this->filename = $filename;
    }
    
    public function writeData(string $data): void {
        file_put_contents($this->filename, $data);
        echo "Données écrites dans le fichier {$this->filename}\n";
    }
    
    public function readData(): string {
        if (file_exists($this->filename)) {
            $data = file_get_contents($this->filename);
            echo "Données lues depuis le fichier {$this->filename}\n";
            return $data;
        }
        return "";
    }
}

// Décorateur de base
abstract class DataSourceDecorator implements DataSource {
    protected DataSource $source;
    
    public function __construct(DataSource $source) {
        $this->source = $source;
    }
    
    public function writeData(string $data): void {
        $this->source->writeData($data);
    }
    
    public function readData(): string {
        return $this->source->readData();
    }
}

// Décorateurs concrets
class EncryptionDecorator extends DataSourceDecorator {
    private string $key;
    
    public function __construct(DataSource $source, string $key) {
        parent::__construct($source);
        $this->key = $key;
    }
    
    public function writeData(string $data): void {
        $encryptedData = $this->encrypt($data);
        echo "Chiffrement des données avec la clé {$this->key}\n";
        parent::writeData($encryptedData);
    }
    
    public function readData(): string {
        $data = parent::readData();
        if (!empty($data)) {
            echo "Déchiffrement des données avec la clé {$this->key}\n";
            return $this->decrypt($data);
        }
        return $data;
    }
    
    private function encrypt(string $data): string {
        return base64_encode($data . "|" . $this->key);
    }
    
    private function decrypt(string $data): string {
        $decoded = base64_decode($data);
        $parts = explode("|", $decoded);
        return $parts[0] ?? "";
    }
}

class CompressionDecorator extends DataSourceDecorator {
    private int $level;
    
    public function __construct(DataSource $source, int $level = 6) {
        parent::__construct($source);
        $this->level = $level;
    }
    
    public function writeData(string $data): void {
        $compressedData = $this->compress($data);
        echo "Compression des données (niveau {$this->level})\n";
        parent::writeData($compressedData);
    }
    
    public function readData(): string {
        $data = parent::readData();
        if (!empty($data)) {
            echo "Décompression des données\n";
            return $this->decompress($data);
        }
        return $data;
    }
    
    private function compress(string $data): string {
        return gzcompress($data, $this->level);
    }
    
    private function decompress(string $data): string {
        return gzuncompress($data) ?: "";
    }
}

// Utilisation
echo "=== Système de Fichiers Décoré ===\n";

$source = new FileDataSource("test.txt");

// Fichier avec chiffrement et compression
$decoratedSource = new EncryptionDecorator(
    new CompressionDecorator($source),
    "secret_key_123"
);

$testData = "Ceci est un message de test pour démontrer le pattern Decorator.";

echo "\n--- Écriture des données ---\n";
$decoratedSource->writeData($testData);

echo "\n--- Lecture des données ---\n";
$readData = $decoratedSource->readData();
echo "Données lues: " . $readData . "\n";

// Interface commune
public interface TextProcessor {
    String process(String text);
    int getProcessingCost();
}

// Composant de base
public class PlainTextProcessor implements TextProcessor {
    @Override
    public String process(String text) {
        return text;
    }
    
    @Override
    public int getProcessingCost() {
        return 1; // Coût de base
    }
}

// Décorateur de base
public abstract class TextProcessorDecorator implements TextProcessor {
    protected TextProcessor processor;
    
    public TextProcessorDecorator(TextProcessor processor) {
        this.processor = processor;
    }
    
    @Override
    public String process(String text) {
        return processor.process(text);
    }
    
    @Override
    public int getProcessingCost() {
        return processor.getProcessingCost();
    }
}

// Décorateurs concrets
public class UpperCaseDecorator extends TextProcessorDecorator {
    public UpperCaseDecorator(TextProcessor processor) {
        super(processor);
    }
    
    @Override
    public String process(String text) {
        String processedText = super.process(text);
        return processedText.toUpperCase();
    }
    
    @Override
    public int getProcessingCost() {
        return super.getProcessingCost() + 1;
    }
}

public class TrimDecorator extends TextProcessorDecorator {
    public TrimDecorator(TextProcessor processor) {
        super(processor);
    }
    
    @Override
    public String process(String text) {
        String processedText = super.process(text);
        return processedText.trim();
    }
    
    @Override
    public int getProcessingCost() {
        return super.getProcessingCost() + 1;
    }
}

public class HtmlEscapeDecorator extends TextProcessorDecorator {
    public HtmlEscapeDecorator(TextProcessor processor) {
        super(processor);
    }
    
    @Override
    public String process(String text) {
        String processedText = super.process(text);
        return escapeHtml(processedText);
    }
    
    @Override
    public int getProcessingCost() {
        return super.getProcessingCost() + 2;
    }
    
    private String escapeHtml(String text) {
        return text.replace("&", "&")
                  .replace("<", "<")
                  .replace(">", ">")
                  .replace("\"", """)
                  .replace("'", "'");
    }
}

// Classe de démonstration
public class DecoratorDemo {
    public static void main(String[] args) {
        System.out.println("=== Système de Traitement de Texte ===");
        
        // Processeur avec plusieurs décorateurs
        TextProcessor processor = new HtmlEscapeDecorator(
            new UpperCaseDecorator(
                new TrimDecorator(
                    new PlainTextProcessor()
                )
            )
        );
        
        String text = "  Hello !  ";
        System.out.println("Texte original: \"" + text + "\"");
        System.out.println("Traitement: \"" + processor.process(text) + "\"");
        System.out.println("Coût: " + processor.getProcessingCost());
    }
}

⚖️ Avantages et Inconvénients

✅ Avantages

  • Flexibilité runtime : Ajout/suppression de fonctionnalités à l'exécution
  • Composition libre : Combinaisons multiples de décorateurs
  • Principe Ouvert/Fermé : Extension sans modification
  • Responsabilité unique : Chaque décorateur a un rôle précis
  • Alternative à l'héritage : Évite l'explosion de classes

❌ Inconvénients

  • Complexité accrue : Nombreux petits objets à gérer
  • Ordre des décorateurs : L'ordre peut affecter le résultat
  • Debugging difficile : Chaîne d'appels complexe à suivre
  • Performance : Overhead des appels multiples
  • Interface identique : Tous les décorateurs doivent implémenter la même interface

🎯 Cas d'Usage Appropriés

✅ Quand l'utiliser

  • Interfaces graphiques : Bordures, scrollbars, ombres
  • Traitement de données : Chiffrement, compression, validation
  • Middleware : Authentification, logging, cache
  • Streams/IO : Buffering, filtering, transformation
  • Services web : Retry, timeout, monitoring

❌ Quand l'éviter

  • Interface complexe : Trop de méthodes à implémenter
  • Fonctionnalités interdépendantes : Décorateurs qui s'influencent
  • Performance critique : Overhead inacceptable
  • Simplicité requise : Pattern trop complexe
  • Peu de variations : Héritage simple suffit

🔄 Alternatives et Patterns Liés

🎯 Strategy Pattern

Changer d'algorithme plutôt que d'ajouter des fonctionnalités

// Différents algorithmes context.setStrategy(new FastStrategy())

🌳 Composite Pattern

Structure hiérarchique vs enrichissement linéaire

// Arbre d'objets parent.add(child1).add(child2)

🔗 Chain of Responsibility

Traitement séquentiel avec possibilité d'arrêt

// Chaîne de handlers handler1.setNext(handler2).handle(request)

🧩 Biais Cognitifs Associés

🎨 Biais de Sur-Décoration

Manifestation : "Ajoutons encore un décorateur pour cette fonctionnalité."

Risque : Créer des chaînes de décorateurs trop longues et complexes.

🔧 Biais de Flexibilité

Manifestation : "Le Decorator rend tout flexible, utilisons-le partout."

Risque : Sur-ingénierie quand des solutions plus simples existent.

📦 Biais de Composition

Manifestation : "La composition est toujours meilleure que l'héritage."

Risque : Éviter l'héritage même quand il est approprié.

⚠️ Anti-Patterns à Éviter

🎪 Decorator Hell

Chaînes de décorateurs trop longues et difficiles à comprendre.

// ❌ Mauvais : Trop de décorateurs new D7(new D6(new D5(new D4(new D3(new D2(new D1(base)))))))

🔄 Ordre Critique

Décorateurs dont l'ordre d'application change complètement le comportement.

// ❌ Problématique : Ordre critique new Encrypt(new Compress(data)) != new Compress(new Encrypt(data))
