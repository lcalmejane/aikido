🔌 Adapter Pattern

Permettre à des interfaces incompatibles de collaborer

🎨 Design Patterns
⭐ Difficulté: Facile
⏱️ 15 min
🏗️ Structurel

🎯 Définition

L'Adapter est un pattern structurel qui permet à des objets ayant des interfaces incompatibles de collaborer ensemble.

❌ Problème Résolu

  • Intégrer une bibliothèque tierce avec une interface différente
  • Faire collaborer du code legacy avec du code moderne
  • Utiliser des services externes avec des formats différents
  • Migrer progressivement vers une nouvelle API

✅ Solution Apportée

  • Interface unifiée pour le client
  • Réutilisation de code existant
  • Séparation des préoccupations
  • Intégration transparente
💡 Analogie : Comme un adaptateur électrique qui permet de brancher un appareil européen sur une prise américaine, l'Adapter fait le pont entre deux interfaces.

Éléments Clés

  • Target : Interface que le client s'attend à utiliser
  • Adaptee : Classe existante avec interface incompatible
  • Adapter : Implémente Target et délègue à Adaptee
  • Client : Utilise Target sans connaître Adaptee

💡 Point clé : L'Adapter fait la traduction bidirectionnelle entre l'interface attendue et l'interface existante.

💻 Implémentations

Exemple : Intégration de Services de Paiement


// Interface cible que notre application utilise
interface PaymentProcessor {
    processPayment(amount: number, currency: string, cardToken: string): Promise<PaymentResult>;
    refundPayment(transactionId: string, amount?: number): Promise<RefundResult>;
    getTransactionStatus(transactionId: string): Promise<TransactionStatus>;
}

interface PaymentResult {
    success: boolean;
    transactionId: string;
    message: string;
    fees?: number;
}

// Service Stripe existant (Adaptee) - Interface incompatible
class StripeService {
    private apiKey: string;
    
    constructor(apiKey: string) {
        this.apiKey = apiKey;
    }
    
    async createCharge(params: {
        amount: number; // en centimes
        currency: string;
        source: string;
        description?: string;
    }): Promise<StripeCharge> {
        console.log(`🔵 Stripe: Création charge ${params.amount} ${params.currency}`);
        
        // Simulation appel API Stripe
        await this.delay(1000);
        
        return {
            id: `ch_${Math.random().toString(36).substr(2, 9)}`,
            amount: params.amount,
            currency: params.currency,
            status: 'succeeded',
            created: Date.now(),
            description: params.description || ''
        };
    }
    
    private delay(ms: number): Promise<void> {
        return new Promise(resolve => setTimeout(resolve, ms));
    }
}

interface StripeCharge {
    id: string;
    amount: number;
    currency: string;
    status: string;
    created: number;
    description: string;
}

// Adapter pour Stripe
class StripeAdapter implements PaymentProcessor {
    private stripeService: StripeService;
    
    constructor(apiKey: string) {
        this.stripeService = new StripeService(apiKey);
    }
    
    async processPayment(amount: number, currency: string, cardToken: string): Promise<PaymentResult> {
        try {
            // Conversion : euros vers centimes pour Stripe
            const amountInCents = Math.round(amount * 100);
            
            const charge = await this.stripeService.createCharge({
                amount: amountInCents,
                currency: currency.toLowerCase(),
                source: cardToken,
                description: `Paiement ${amount} ${currency.toUpperCase()}`
            });
            
            return {
                success: charge.status === 'succeeded',
                transactionId: charge.id,
                message: charge.status === 'succeeded' ? 'Paiement réussi' : 'Paiement échoué',
                fees: amountInCents * 0.029 + 30 // Frais Stripe typiques
            };
            
        } catch (error) {
            return {
                success: false,
                transactionId: '',
                message: `Erreur Stripe: ${error.message}`
            };
        }
    }
    
    async refundPayment(transactionId: string, amount?: number): Promise<RefundResult> {
        // Implémentation du remboursement
        return {
            success: true,
            refundId: `re_${Math.random().toString(36).substr(2, 9)}`,
            message: 'Remboursement réussi'
        };
    }
    
    async getTransactionStatus(transactionId: string): Promise<TransactionStatus> {
        // Implémentation de la vérification de statut
        return {
            id: transactionId,
            status: 'completed',
            amount: 25.99,
            currency: 'EUR'
        };
    }
}

// Utilisation unifiée
async function demonstratePaymentAdapter() {
    const processor: PaymentProcessor = new StripeAdapter('sk_test_...');
    
    const result = await processor.processPayment(25.99, 'EUR', 'card_token_123');
    console.log(`Paiement: ${result.success ? '✅' : '❌'} ${result.message}`);
}

// Interface cible pour notre système de logging
interface Logger {
    public function log(string $level, string $message, array $context = []): void;
    public function info(string $message, array $context = []): void;
    public function warning(string $message, array $context = []): void;
    public function error(string $message, array $context = []): void;
}

// Service de logging legacy (Adaptee) - Interface différente
class LegacyLogger {
    private string $logFile;
    private $handle;
    
    public function __construct(string $logFile = 'app.log') {
        $this->logFile = $logFile;
        $this->handle = fopen($logFile, 'a');
    }
    
    public function writeLog(string $type, string $msg, string $extra = ''): bool {
        if (!$this->handle) {
            return false;
        }
        
        $timestamp = date('d/m/Y H:i:s');
        $logLine = "[{$timestamp}] [{$type}] {$msg}";
        
        if ($extra) {
            $logLine .= " | Extra: {$extra}";
        }
        
        $logLine .= "\n";
        
        fwrite($this->handle, $logLine);
        fflush($this->handle);
        
        echo "📝 Legacy: {$logLine}";
        
        return true;
    }
    
    public function logInfo(string $message): void {
        $this->writeLog('INFO', $message);
    }
    
    public function logWarning(string $message): void {
        $this->writeLog('WARN', $message);
    }
    
    public function logError(string $message): void {
        $this->writeLog('ERROR', $message);
    }
    
    public function __destruct() {
        if ($this->handle) {
            fclose($this->handle);
        }
    }
}

// Adapter pour le système legacy
class LegacyLoggerAdapter implements Logger {
    private LegacyLogger $legacyLogger;
    
    public function __construct(string $logFile = 'app.log') {
        $this->legacyLogger = new LegacyLogger($logFile);
    }
    
    public function log(string $level, string $message, array $context = []): void {
        $contextString = !empty($context) ? json_encode($context) : '';
        
        switch (strtolower($level)) {
            case 'info':
                $this->legacyLogger->logInfo($message);
                break;
            case 'warning':
            case 'warn':
                $this->legacyLogger->logWarning($message);
                break;
            case 'error':
                $this->legacyLogger->logError($message);
                break;
            default:
                // Pour les autres niveaux, utiliser writeLog directement
                $this->legacyLogger->writeLog(strtoupper($level), $message, $contextString);
        }
    }
    
    public function info(string $message, array $context = []): void {
        $this->legacyLogger->logInfo($message);
        if (!empty($context)) {
            $this->legacyLogger->writeLog('INFO', 'Context: ' . json_encode($context));
        }
    }
    
    public function warning(string $message, array $context = []): void {
        $this->legacyLogger->logWarning($message);
        if (!empty($context)) {
            $this->legacyLogger->writeLog('WARN', 'Context: ' . json_encode($context));
        }
    }
    
    public function error(string $message, array $context = []): void {
        $this->legacyLogger->logError($message);
        if (!empty($context)) {
            $this->legacyLogger->writeLog('ERROR', 'Context: ' . json_encode($context));
        }
    }
}

// Utilisation unifiée
function demonstrateLoggerAdapter(): void {
    echo "=== Test Adapter de Logging ===\n\n";
    
    $logger = new LegacyLoggerAdapter('legacy.log');
    
    $logger->info("Application démarrée", ['version' => '1.0.0']);
    $logger->warning("Mémoire faible", ['usage' => '85%']);
    $logger->error("Connexion échouée", ['host' => 'localhost']);
}

// Interface cible pour notre système de notification
interface NotificationSender {
    void sendNotification(String recipient, String subject, String message);
    boolean isRecipientValid(String recipient);
    NotificationResult getDeliveryStatus(String notificationId);
}

class NotificationResult {
    private final String id;
    private final boolean delivered;
    private final String status;
    
    public NotificationResult(String id, boolean delivered, String status) {
        this.id = id;
        this.delivered = delivered;
        this.status = status;
    }
    
    public String getId() { return id; }
    public boolean isDelivered() { return delivered; }
    public String getStatus() { return status; }
}

// Service email existant (Adaptee) - Interface spécifique
class JavaMailService {
    private String smtpHost;
    private String username;
    private String password;
    
    public JavaMailService(String smtpHost, String username, String password) {
        this.smtpHost = smtpHost;
        this.username = username;
        this.password = password;
    }
    
    public EmailResult sendEmail(EmailMessage emailMessage) throws EmailException {
        System.out.println("📧 JavaMail: Envoi email vers " + emailMessage.getToAddress());
        
        // Validation de l'adresse email
        if (!isValidEmailAddress(emailMessage.getToAddress())) {
            throw new EmailException("Adresse email invalide: " + emailMessage.getToAddress());
        }
        
        // Simulation de l'envoi
        try {
            Thread.sleep(500);
            
            String messageId = "email_" + System.currentTimeMillis();
            System.out.println("✅ Email envoyé avec succès - ID: " + messageId);
            
            return new EmailResult(messageId, true, "DELIVERED");
            
        } catch (InterruptedException e) {
            throw new EmailException("Erreur lors de l'envoi: " + e.getMessage());
        }
    }
    
    private boolean isValidEmailAddress(String email) {
        return email != null && email.contains("@") && email.contains(".");
    }
}

// Classes pour JavaMail
class EmailMessage {
    private String toAddress;
    private String subject;
    private String body;
    
    public EmailMessage(String toAddress, String subject, String body) {
        this.toAddress = toAddress;
        this.subject = subject;
        this.body = body;
    }
    
    public String getToAddress() { return toAddress; }
    public String getSubject() { return subject; }
    public String getBody() { return body; }
}

class EmailResult {
    private final String messageId;
    private final boolean success;
    private final String status;
    
    public EmailResult(String messageId, boolean success, String status) {
        this.messageId = messageId;
        this.success = success;
        this.status = status;
    }
    
    public String getMessageId() { return messageId; }
    public boolean isSuccess() { return success; }
    public String getStatus() { return status; }
}

class EmailException extends Exception {
    public EmailException(String message) {
        super(message);
    }
}

// Adapter pour JavaMail
class EmailNotificationAdapter implements NotificationSender {
    private JavaMailService emailService;
    private String fromAddress;
    
    public EmailNotificationAdapter(JavaMailService emailService, String fromAddress) {
        this.emailService = emailService;
        this.fromAddress = fromAddress;
    }
    
    @Override
    public void sendNotification(String recipient, String subject, String message) {
        try {
            EmailMessage emailMessage = new EmailMessage(recipient, subject, message);
            EmailResult result = emailService.sendEmail(emailMessage);
            
            if (!result.isSuccess()) {
                throw new RuntimeException("Échec envoi email: " + result.getStatus());
            }
            
        } catch (EmailException e) {
            throw new RuntimeException("Erreur adapter email: " + e.getMessage(), e);
        }
    }
    
    @Override
    public boolean isRecipientValid(String recipient) {
        return recipient != null && recipient.contains("@") && recipient.contains(".");
    }
    
    @Override
    public NotificationResult getDeliveryStatus(String notificationId) {
        // Simulation de vérification de statut
        return new NotificationResult(notificationId, true, "DELIVERED");
    }
}

// Utilisation
public class NotificationAdapterDemo {
    public static void main(String[] args) {
        JavaMailService emailService = new JavaMailService(
            "smtp.gmail.com", "user@gmail.com", "password"
        );
        
        NotificationSender sender = new EmailNotificationAdapter(
            emailService, "noreply@myapp.com"
        );
        
        try {
            sender.sendNotification(
                "user@example.com",
                "Test Notification",
                "Ceci est un message de test"
            );
            
            System.out.println("✅ Notification envoyée avec succès");
            
        } catch (Exception e) {
            System.err.println("❌ Erreur: " + e.getMessage());
        }
    }
}

⚖️ Avantages et Inconvénients

✅ Avantages

  • Réutilisation de code : Intégration de code existant sans modification
  • Séparation des préoccupations : Interface client découplée de l'implémentation
  • Flexibilité : Changement d'implémentation transparent
  • Compatibilité : Fait collaborer des systèmes incompatibles
  • Migration progressive : Transition en douceur vers nouvelles APIs

❌ Inconvénients

  • Complexité ajoutée : Couche supplémentaire à maintenir
  • Performance : Indirection et traduction des données
  • Perte de fonctionnalités : Interface cible peut être limitante
  • Debugging difficile : Erreurs peuvent être masquées
  • Maintenance : Évolution des deux interfaces à gérer

🎯 Cas d'Usage Appropriés

✅ Quand l'utiliser

  • Intégration de bibliothèques : APIs tierces incompatibles
  • Code legacy : Modernisation progressive
  • Services externes : Formats de données différents
  • Migration d'API : Transition vers nouvelle version
  • Standardisation : Interface unifiée pour plusieurs implémentations

❌ Quand l'éviter

  • Interfaces compatibles : Pas de différence significative
  • Performance critique : Latence inacceptable
  • Contrôle total : Possibilité de modifier l'interface source
  • Fonctionnalités riches : Perte importante de fonctionnalités
  • Maintenance complexe : Évolution rapide des interfaces

🔄 Alternatives et Patterns Liés

🏗️ Facade Pattern

Simplifier l'interface au lieu de l'adapter

// Interface simplifiée pour système complexe facade.processOrder(orderData);

🔗 Bridge Pattern

Séparer abstraction et implémentation

// Découplage abstraction/implémentation new RemoteControl(new SonyTV());

🛡️ Proxy Pattern

Contrôler l'accès au lieu d'adapter

// Contrôle d'accès transparent new SecurityProxy(realService);

🧩 Biais Cognitifs Associés

🔧 Biais de l'Outil

Manifestation : "J'ai cette bibliothèque, créons un adapter pour l'utiliser partout."

Risque : Forcer l'utilisation d'une solution inadaptée via des adapters complexes.

💸 Coût Irrécupérable

Manifestation : "On a déjà ce code legacy, adaptons-le au lieu de le réécrire."

Risque : Maintenir du code obsolète par peur de perdre l'investissement initial.

🎯 Biais de Simplicité

Manifestation : "Un adapter, c'est simple et rapide à implémenter."

Risque : Sous-estimer la complexité de maintenance à long terme.

⚠️ Anti-Patterns à Éviter

🔄 Adapter Chain

Chaîner plusieurs adapters créant une complexité excessive.

// ❌ Mauvais : Chaîne d'adapters new AdapterC(new AdapterB(new AdapterA(legacyService)));

🧠 Smart Adapter

Un adapter qui ajoute trop de logique métier au lieu de juste adapter.

// ❌ Adapter qui fait trop de choses class SmartAdapter { // Adaptation + validation + transformation + cache + logging... }
