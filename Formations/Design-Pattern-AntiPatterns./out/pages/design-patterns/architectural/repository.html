🗄️ Repository Pattern

Encapsuler la logique d'accès aux données

🎨 Design Patterns
⭐ Difficulté: Facile
⏱️ 15 min
🏗️ Architectural

🎯 Définition

Le Repository est un pattern architectural qui encapsule la logique nécessaire pour accéder aux sources de données. Il centralise les fonctionnalités communes d'accès aux données, offrant une meilleure maintenabilité et découplant l'infrastructure d'accès aux données de la couche métier.

❌ Problème Résolu

  • Couplage fort entre logique métier et accès aux données
  • Duplication de code d'accès aux données
  • Difficulté à tester la logique métier
  • Changement de source de données complexe

✅ Solution Apportée

  • Séparation claire des responsabilités
  • Code d'accès centralisé et réutilisable
  • Facilite les tests avec des mocks
  • Abstraction de la source de données
💡 Analogie : Comme une bibliothèque qui organise les livres et fournit des méthodes pour les rechercher, le Repository organise les données et fournit des méthodes pour y accéder.

Éléments Clés

  • IRepository : Interface définissant les opérations d'accès aux données
  • ConcreteRepository : Implémentation spécifique (base de données, fichier, API)
  • Entity : Objet métier manipulé par le repository
  • Service : Couche métier utilisant le repository

💡 Point clé : Le service ne connaît que l'interface, permettant de changer d'implémentation sans impact sur la logique métier.

💻 Implémentations

Exemple : Repository d'Utilisateurs


// Entité User
interface User {
    id: string;
    name: string;
    email: string;
    createdAt: Date;
}

// Interface du Repository
interface IUserRepository {
    findById(id: string): Promise<User | null>;
    findAll(): Promise<User[]>;
    findByEmail(email: string): Promise<User | null>;
    save(user: User): Promise<User>;
    delete(id: string): Promise<void>;
}

// Implémentation avec base de données
class DatabaseUserRepository implements IUserRepository {
    constructor(private connection: DatabaseConnection) {}

    async findById(id: string): Promise<User | null> {
        const query = 'SELECT * FROM users WHERE id = ?';
        const result = await this.connection.query(query, [id]);
        
        if (result.length === 0) {
            return null;
        }
        
        return this.mapRowToUser(result[0]);
    }

    async findAll(): Promise<User[]> {
        const query = 'SELECT * FROM users ORDER BY created_at DESC';
        const results = await this.connection.query(query);
        
        return results.map(row => this.mapRowToUser(row));
    }

    async findByEmail(email: string): Promise<User | null> {
        const query = 'SELECT * FROM users WHERE email = ?';
        const result = await this.connection.query(query, [email]);
        
        if (result.length === 0) {
            return null;
        }
        
        return this.mapRowToUser(result[0]);
    }

    async save(user: User): Promise<User> {
        if (user.id) {
            // Mise à jour
            const query = 'UPDATE users SET name = ?, email = ? WHERE id = ?';
            await this.connection.query(query, [user.name, user.email, user.id]);
        } else {
            // Création
            const id = this.generateId();
            const query = 'INSERT INTO users (id, name, email, created_at) VALUES (?, ?, ?, ?)';
            await this.connection.query(query, [id, user.name, user.email, new Date()]);
            user.id = id;
        }
        
        return user;
    }

    async delete(id: string): Promise<void> {
        const query = 'DELETE FROM users WHERE id = ?';
        await this.connection.query(query, [id]);
    }

    private mapRowToUser(row: any): User {
        return {
            id: row.id,
            name: row.name,
            email: row.email,
            createdAt: new Date(row.created_at)
        };
    }

    private generateId(): string {
        return Math.random().toString(36).substr(2, 9);
    }
}

// Service utilisant le Repository
class UserService {
    constructor(private userRepository: IUserRepository) {}

    async createUser(name: string, email: string): Promise<User> {
        // Vérifier si l'email existe déjà
        const existingUser = await this.userRepository.findByEmail(email);
        if (existingUser) {
            throw new Error('Un utilisateur avec cet email existe déjà');
        }

        const user: User = {
            id: '',
            name,
            email,
            createdAt: new Date()
        };

        return await this.userRepository.save(user);
    }

    async getUserById(id: string): Promise<User> {
        const user = await this.userRepository.findById(id);
        if (!user) {
            throw new Error('Utilisateur non trouvé');
        }
        return user;
    }
}


<?php

// Entité User
class User {
    public function __construct(
        public ?string $id = null,
        public string $name = '',
        public string $email = '',
        public ?DateTime $createdAt = null
    ) {
        $this->createdAt = $this->createdAt ?? new DateTime();
    }
}

// Interface du Repository
interface UserRepositoryInterface {
    public function findById(string $id): ?User;
    public function findAll(): array;
    public function findByEmail(string $email): ?User;
    public function save(User $user): User;
    public function delete(string $id): void;
}

// Implémentation avec PDO
class DatabaseUserRepository implements UserRepositoryInterface {
    private PDO $pdo;

    public function __construct(PDO $pdo) {
        $this->pdo = $pdo;
    }

    public function findById(string $id): ?User {
        $stmt = $this->pdo->prepare('SELECT * FROM users WHERE id = ?');
        $stmt->execute([$id]);
        $row = $stmt->fetch(PDO::FETCH_ASSOC);
        
        return $row ? $this->mapRowToUser($row) : null;
    }

    public function findAll(): array {
        $stmt = $this->pdo->query('SELECT * FROM users ORDER BY created_at DESC');
        $rows = $stmt->fetchAll(PDO::FETCH_ASSOC);
        
        return array_map([$this, 'mapRowToUser'], $rows);
    }

    public function save(User $user): User {
        if ($user->id) {
            // Mise à jour
            $stmt = $this->pdo->prepare(
                'UPDATE users SET name = ?, email = ? WHERE id = ?'
            );
            $stmt->execute([$user->name, $user->email, $user->id]);
        } else {
            // Création
            $user->id = $this->generateId();
            $stmt = $this->pdo->prepare(
                'INSERT INTO users (id, name, email, created_at) VALUES (?, ?, ?, ?)'
            );
            $stmt->execute([
                $user->id, 
                $user->name, 
                $user->email, 
                $user->createdAt->format('Y-m-d H:i:s')
            ]);
        }
        
        return $user;
    }

    private function mapRowToUser(array $row): User {
        return new User(
            $row['id'],
            $row['name'],
            $row['email'],
            new DateTime($row['created_at'])
        );
    }

    private function generateId(): string {
        return uniqid('user_', true);
    }
}

// Interface du Repository
public interface UserRepository {
    Optional<User> findById(String id);
    List<User> findAll();
    Optional<User> findByEmail(String email);
    User save(User user);
    void delete(String id);
}

// Implémentation avec JPA
@Repository
public class JpaUserRepository implements UserRepository {
    
    @PersistenceContext
    private EntityManager entityManager;
    
    @Override
    public Optional<User> findById(String id) {
        User user = entityManager.find(User.class, id);
        return Optional.ofNullable(user);
    }
    
    @Override
    public List<User> findAll() {
        TypedQuery<User> query = entityManager.createQuery(
            "SELECT u FROM User u ORDER BY u.createdAt DESC", User.class);
        return query.getResultList();
    }
    
    @Override
    @Transactional
    public User save(User user) {
        if (user.getId() == null) {
            user.setId(generateId());
            entityManager.persist(user);
        } else {
            user = entityManager.merge(user);
        }
        return user;
    }
    
    private String generateId() {
        return UUID.randomUUID().toString();
    }
}

// Service utilisant le Repository
@Service
public class UserService {
    private final UserRepository userRepository;
    
    public UserService(UserRepository userRepository) {
        this.userRepository = userRepository;
    }
    
    public User createUser(String name, String email) {
        User user = new User();
        user.setName(name);
        user.setEmail(email);
        
        return userRepository.save(user);
    }
}

⚖️ Avantages et Inconvénients

✅ Avantages

  • Séparation des responsabilités : Découple la logique métier de l'accès aux données
  • Testabilité : Facilite les tests unitaires avec des mocks
  • Flexibilité : Changement de source de données sans impact
  • Réutilisabilité : Code d'accès centralisé et réutilisable
  • Maintenabilité : Évite la duplication de code

❌ Inconvénients

  • Complexité supplémentaire : Ajoute une couche d'abstraction
  • Over-engineering : Peut être excessif pour des applications simples
  • Performance : Couche supplémentaire peut impacter les performances
  • Courbe d'apprentissage : Nécessite une compréhension des patterns

🎯 Cas d'Usage Appropriés

✅ Quand l'utiliser

  • Applications complexes : Avec plusieurs sources de données
  • Tests unitaires : Quand la testabilité est importante
  • Évolutivité : Quand la source de données peut changer
  • Équipes multiples : Séparation claire des responsabilités

❌ Quand l'éviter

  • Applications simples : CRUD basique avec une seule source
  • Prototypes rapides : Quand la rapidité prime sur l'architecture
  • Équipe débutante : Complexité supplémentaire non justifiée
  • Performance critique : Quand chaque milliseconde compte

🧩 Biais Cognitifs Associés

🏗️ Biais de l'Architecture Parfaite

Manifestation : "Il faut absolument utiliser Repository partout pour avoir une architecture propre."

Risque : Over-engineering et complexité inutile pour des cas simples.

🔮 Biais de Prédiction

Manifestation : "On va sûrement changer de base de données, donc utilisons Repository."

Risque : Optimisation prématurée pour des besoins hypothétiques.

📚 Biais du Livre de Patterns

Manifestation : Appliquer Repository parce que c'est dans les livres de patterns.

Risque : Utilisation sans évaluer la pertinence pour le contexte spécifique.
