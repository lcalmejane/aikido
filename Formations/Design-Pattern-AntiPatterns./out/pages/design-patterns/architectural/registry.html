📋 Registry Pattern

Point d'accès global pour retrouver des objets et services

🎨 Design Patterns
⭐ Difficulté: Facile
⏱️ 15 min
🏗️ Architectural

🎯 Définition

Le Registry est un pattern architectural qui fournit un point d'accès global pour retrouver des objets et services dans l'application. Il agit comme un annuaire centralisé où les composants peuvent s'enregistrer et être retrouvés par d'autres parties du système.

❌ Problème Résolu

  • Localisation difficile des services dans l'application
  • Couplage fort entre composants
  • Configuration complexe des dépendances
  • Besoin d'accès global à des services

✅ Solution Apportée

  • Centralisation de l'enregistrement des services
  • Découplage entre composants
  • Changement d'implémentation à l'exécution
  • Interface simple pour la gestion des services
💡 Analogie : Comme un annuaire téléphonique qui permet de retrouver le numéro d'une personne par son nom, le Registry permet de retrouver un service par son identifiant.

Éléments Clés

  • Registry : Classe centrale gérant l'enregistrement et la récupération
  • services : Collection stockant les services par nom
  • register() : Méthode pour enregistrer un service
  • get() : Méthode pour récupérer un service par nom

// Registry simple
class Registry {
    private static instance: Registry;
    private services: Map<string, any> = new Map();

    private constructor() {}

    static getInstance(): Registry {
        if (!Registry.instance) {
            Registry.instance = new Registry();
        }
        return Registry.instance;
    }

    register<T>(name: string, service: T): void {
        this.services.set(name, service);
    }

    get<T>(name: string): T | undefined {
        return this.services.get(name) as T;
    }

    has(name: string): boolean {
        return this.services.has(name);
    }

    unregister(name: string): void {
        this.services.delete(name);
    }

    clear(): void {
        this.services.clear();
    }

    getAll(): Map<string, any> {
        return new Map(this.services);
    }
}

// Registry avec types et factory
interface ServiceFactory<T> {
    create(): T;
}

class TypedRegistry {
    private static instance: TypedRegistry;
    private services: Map<string, any> = new Map();
    private factories: Map<string, ServiceFactory<any>> = new Map();

    private constructor() {}

    static getInstance(): TypedRegistry {
        if (!TypedRegistry.instance) {
            TypedRegistry.instance = new TypedRegistry();
        }
        return TypedRegistry.instance;
    }

    // Enregistrer une instance
    registerInstance<T>(name: string, service: T): void {
        this.services.set(name, service);
    }

    // Enregistrer une factory
    registerFactory<T>(name: string, factory: ServiceFactory<T>): void {
        this.factories.set(name, factory);
    }

    // Récupérer un service (instance ou création via factory)
    get<T>(name: string): T | undefined {
        // D'abord chercher une instance existante
        if (this.services.has(name)) {
            return this.services.get(name) as T;
        }

        // Sinon utiliser la factory si disponible
        if (this.factories.has(name)) {
            const factory = this.factories.get(name)!;
            const instance = factory.create();
            this.services.set(name, instance); // Cache l'instance
            return instance as T;
        }

        return undefined;
    }

    // Récupérer une nouvelle instance via factory (sans cache)
    create<T>(name: string): T | undefined {
        if (this.factories.has(name)) {
            const factory = this.factories.get(name)!;
            return factory.create() as T;
        }
        return undefined;
    }
}

class UserService {
    private logger: Logger;

    constructor() {
        const registry = TypedRegistry.getInstance();
        this.logger = registry.get<Logger>('logger')!;

        } catch (error) {
            this.logger.log(`Error creating user: ${error}`);
            throw error;
        }
    }
}

// Registry simple
class Registry {
    private static $instance = null;
    private $services = [];

    private function __construct() {}

    // Empêcher le clonage
    private function __clone() {}

    // Empêcher la désérialisation
    public function __wakeup() {
        throw new Exception("Impossible de désérialiser un Singleton");
    }

    public static function getInstance(): Registry {
        if (self::$instance === null) {
            self::$instance = new self();
        }
        return self::$instance;
    }

    public function register(string $name, $service): void {
        $this->services[$name] = $service;
    }

    public function get(string $name) {
        return $this->services[$name] ?? null;
    }

    public function has(string $name): bool {
        return isset($this->services[$name]);
    }

    public function unregister(string $name): void {
        unset($this->services[$name]);
    }

    public function clear(): void {
        $this->services = [];
    }

    public function getAll(): array {
        return $this->services;
    }
}

// Interface pour les factories
interface ServiceFactory {
    public function create();
}

// Registry avec support des factories
class TypedRegistry {
    private static $instance = null;
    private $services = [];
    private $factories = [];

    private function __construct() {}

    public static function getInstance(): TypedRegistry {
        if (self::$instance === null) {
            self::$instance = new self();
        }
        return self::$instance;
    }

    public function registerInstance(string $name, $service): void {
        $this->services[$name] = $service;
    }

    public function registerFactory(string $name, ServiceFactory $factory): void {
        $this->factories[$name] = $factory;
    }

    public function get(string $name) {
        // Chercher une instance existante
        if (isset($this->services[$name])) {
            return $this->services[$name];
        }

        // Utiliser la factory si disponible
        if (isset($this->factories[$name])) {
            $factory = $this->factories[$name];
            $instance = $factory->create();
            $this->services[$name] = $instance; // Cache l'instance
            return $instance;
        }

        return null;
    }
}

// Registry simple
public class Registry {
    private static Registry instance;
    private Map<String, Object> services = new HashMap<>();

    private Registry() {}

    public static synchronized Registry getInstance() {
        if (instance == null) {
            instance = new Registry();
        }
        return instance;
    }

    public <T> void register(String name, T service) {
        services.put(name, service);
    }

    @SuppressWarnings("unchecked")
    public <T> T get(String name, Class<T> type) {
        Object service = services.get(name);
        if (service != null && type.isInstance(service)) {
            return (T) service;
        }
        return null;
    }

    public boolean has(String name) {
        return services.containsKey(name);
    }

    public void unregister(String name) {
        services.remove(name);
    }

    public void clear() {
        services.clear();
    }
}

// Interface pour les factories
public interface ServiceFactory<T> {
    T create();
}

// Registry avec support des factories
public class TypedRegistry {
    private static TypedRegistry instance;
    private Map<String, Object> services = new HashMap<>();
    private Map<String, ServiceFactory<?>> factories = new HashMap<>();

    private TypedRegistry() {}

    public static synchronized TypedRegistry getInstance() {
        if (instance == null) {
            instance = new TypedRegistry();
        }
        return instance;
    }

    public <T> void registerInstance(String name, T service) {
        services.put(name, service);
    }

    public <T> void registerFactory(String name, ServiceFactory<T> factory) {
        factories.put(name, factory);
    }

    @SuppressWarnings("unchecked")
    public <T> T get(String name, Class<T> type) {
        // Chercher une instance existante
        Object service = services.get(name);
        if (service != null && type.isInstance(service)) {
            return (T) service;
        }

        // Utiliser la factory si disponible
        ServiceFactory<?> factory = factories.get(name);
        if (factory != null) {
            Object instance = factory.create();
            if (type.isInstance(instance)) {
                services.put(name, instance); // Cache l'instance
                return (T) instance;
            }
        }

        return null;
    }
}

// Exemples de services
public interface Logger {
    void log(String message);
}

public class ConsoleLogger implements Logger {
    @Override
    public void log(String message) {
        System.out.println("[LOG] " + LocalDateTime.now() + ": " + message);
    }
}

public class FileLogger implements Logger {
    private String filename;

    public FileLogger(String filename) {
        this.filename = filename;
    }

    @Override
    public void log(String message) {
        try (FileWriter writer = new FileWriter(filename, true)) {
            writer.write("[" + LocalDateTime.now() + "] " + message + "\n");
        } catch (IOException e) {
            System.err.println("Error writing to log file: " + e.getMessage());
        }
    }
}

            // Logique de création d'utilisateur

            logger.log("Error creating user: " + e.getMessage());

⚖️ Avantages et Inconvénients

✅ Avantages

  • Centralisation : Point unique pour enregistrer et retrouver des services
  • Découplage : Les composants ne se connaissent pas directement
  • Flexibilité : Changement d'implémentation à l'exécution
  • Simplicité : Interface simple pour la gestion des services
  • Configuration : Facilite la configuration selon l'environnement

❌ Inconvénients

  • État global : Peut créer des dépendances cachées
  • Tests difficiles : État partagé complique les tests
  • Couplage au Registry : Tous les composants dépendent du Registry
  • Erreurs à l'exécution : Services manquants détectés tardivement
  • Thread-safety : Nécessite une gestion de la concurrence

🎯 Cas d'Usage Appropriés

✅ Quand l'utiliser

  • Configuration de services : Différents services selon l'environnement
  • Plugin system : Enregistrement dynamique d'extensions
  • Tests unitaires : Remplacement facile par des mocks
  • Inversion de contrôle simple : Alternative légère à un conteneur IoC

❌ Quand l'éviter

  • Applications simples : Complexité non justifiée
  • Dépendances explicites : Quand l'injection directe est préférable
  • Performance critique : Lookup dynamique peut être coûteux
  • Type safety importante : Perte de vérification à la compilation

🧩 Biais Cognitifs Associés

🌐 Biais de l'État Global

Manifestation : "Le Registry est pratique, mettons tout dedans !"

Risque : Abuser du Registry comme variable globale, créant des dépendances cachées difficiles à tracer.

🔧 Biais de la Solution Universelle

Manifestation : Vouloir tout mettre dans le Registry, même les objets qui n'ont pas besoin d'être partagés.

Risque : Complexité inutile et perte de clarté dans les dépendances.

🎯 Biais de Simplicité Apparente

Manifestation : "C'est plus simple qu'un conteneur IoC complet."

Risque : Sous-estimer les problèmes de maintenance et de testabilité à long terme.

🎯 Exercice Pratique

Scenario : Système de Plugins

Vous développez une application modulaire où différents plugins peuvent s'enregistrer dynamiquement. Ces plugins fournissent des fonctionnalités comme l'authentification, la notification, ou le stockage. L'application doit pouvoir découvrir et utiliser ces plugins sans les connaître à l'avance.

Question :

Comment organiseriez-vous la découverte et l'utilisation de ces plugins ?

📋 Utiliser un Registry pour enregistrer les plugins
👑 Créer un Singleton pour chaque type de plugin
📊 Utiliser des classes statiques pour chaque plugin

✅ Excellente réponse !

Le Registry est parfait pour ce cas d'usage car :

  • Découverte dynamique : Les plugins peuvent s'enregistrer à l'exécution
  • Découplage : L'application ne connaît pas les plugins à l'avance
  • Flexibilité : Ajout/suppression de plugins sans modification du code
  • Interface uniforme : Tous les plugins sont accessibles de la même manière
// Plugin s'enregistre lui-même
PluginRegistry.register('auth', new OAuth2Plugin());
PluginRegistry.register('storage', new S3Plugin());

// Application utilise les plugins
const authPlugin = PluginRegistry.get('auth');
const storagePlugin = PluginRegistry.get('storage');

⚠️ Pas optimal

Un Singleton par plugin pose plusieurs problèmes :

  • Rigidité : Impossible d'avoir plusieurs instances du même type
  • Couplage : L'application doit connaître chaque Singleton
  • Tests difficiles : État global partagé
  • Pas de découverte : Les plugins doivent être connus à l'avance

❌ Mauvaise approche

Les classes statiques ne conviennent pas car :

  • Pas d'interface commune : Chaque plugin a sa propre API
  • Couplage fort : L'application doit importer chaque classe
  • Pas de polymorphisme : Impossible de traiter les plugins uniformément
  • Configuration difficile : Pas de point central de gestion
