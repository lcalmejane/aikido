🏢 Abstract Factory Pattern

Créer des familles d'objets liés sans spécifier leurs classes concrètes

🎨 Design Patterns
⭐ Difficulté: Avancé
⏱️ 25 min
🏢 Création

🎯 Définition

L'Abstract Factory est un pattern de création qui fournit une interface pour créer des familles d'objets liés ou dépendants sans spécifier leurs classes concrètes.

❌ Problème Résolu

  • Créer des familles d'objets cohérents ensemble
  • Éviter l'incompatibilité entre produits de différentes familles
  • Isoler les classes concrètes du client
  • Faciliter l'échange de familles de produits

✅ Solution Apportée

  • Interface commune pour créer des familles
  • Garantie de cohérence entre produits
  • Découplage client/implémentations concrètes
  • Facilité d'ajout de nouvelles familles
💡 Principe clé : "Créer des familles d'objets liés en garantissant leur cohérence et compatibilité mutuelle."

🏗️ Structure UML

+ createProductA(): AbstractProductA
+ createProductB(): AbstractProductB
ConcreteFactory1

+ operationA(): void
ProductA1

Éléments Clés

  • AbstractFactory : Interface pour créer des familles de produits
  • ConcreteFactory : Implémente la création d'une famille spécifique
  • AbstractProduct : Interface commune pour chaque type de produit
  • ConcreteProduct : Implémentation spécifique d'un produit dans une famille

💡 Point clé : Tous les produits créés par une même factory appartiennent à la même famille et sont compatibles entre eux.

class MacWindow implements Window {
    render(): void {

    }

        console.log("🔴 Fermeture fenêtre macOS");
    }

// Abstract Factory
interface UIFactory {
    createButton(): Button;
    createWindow(): Window;
}

// Concrete Factories
class WindowsUIFactory implements UIFactory {
    createButton(): Button {
        return new WindowsButton();
    }
    
    createWindow(): Window {
        return new WindowsWindow();
    }
}

class MacUIFactory implements UIFactory {
    createButton(): Button {
        return new MacButton();
    }
    
    createWindow(): Window {
        return new MacWindow();
    }
}

// Client utilisant la factory
class Application {
    private factory: UIFactory;
    private button: Button;
    private window: Window;
    
    constructor(factory: UIFactory) {
        this.factory = factory;
        this.button = factory.createButton();
        this.window = factory.createWindow();
    }
    
    render(): void {
        this.window.render();
        this.button.render();
        this.button.onClick(() => {
            console.log("Action du bouton exécutée");
        });
    }
}

// Utilisation
const platform = process.platform;
let factory: UIFactory;

if (platform === 'win32') {
    factory = new WindowsUIFactory();
} else if (platform === 'darwin') {
    factory = new MacUIFactory();
} else {
    factory = new WindowsUIFactory(); // Par défaut
}

const app = new Application(factory);
app.render();

// Factory Provider pour simplifier la sélection
class UIFactoryProvider {
    private static factories = new Map UIFactory>([
        ['windows', () => new WindowsUIFactory()],
        ['macos', () => new MacUIFactory()],
        ['linux', () => new WindowsUIFactory()] // Réutilise Windows pour Linux
    ]);
    
    static getFactory(platform: string): UIFactory {
        const factoryCreator = this.factories.get(platform.toLowerCase());
        if (!factoryCreator) {
            throw new Error(`Plateforme non supportée: ${platform}`);
        }
        return factoryCreator();
    }
    
    static getSupportedPlatforms(): string[] {
        return Array.from(this.factories.keys());
    }
}

// Service d'application avec factory provider
class UIService {
    private factory: UIFactory;
    
    constructor(platform: string) {
        this.factory = UIFactoryProvider.getFactory(platform);
    }
    
    createInterface(): { button: Button; window: Window } {
        return {
            button: this.factory.createButton(),
            window: this.factory.createWindow()
        };
    }
}

// Utilisation simplifiée
const uiService = new UIService('windows');
const { button, window } = uiService.createInterface();

window.render();
button.render();

// Abstract Factory
interface DataStackFactory {
    public function createDatabase(): DatabaseConnection;
    public function createCache(): CacheProvider;
}

// Concrete Factories
class MySQLRedisFactory implements DataStackFactory {
    private string $dbHost;
    private string $cacheHost;
    
    public function __construct(string $dbHost = 'localhost', string $cacheHost = 'localhost') {
        $this->dbHost = $dbHost;
        $this->cacheHost = $cacheHost;
    }
    
    public function createDatabase(): DatabaseConnection {
        return new MySQLConnection($this->dbHost);
    }
    
    public function createCache(): CacheProvider {
        return new RedisCache($this->cacheHost);
    }
}

class PostgreSQLMemcachedFactory implements DataStackFactory {
    private string $dbHost;
    private string $cacheHost;
    
    public function __construct(string $dbHost = 'localhost', string $cacheHost = 'localhost') {
        $this->dbHost = $dbHost;
        $this->cacheHost = $cacheHost;
    }
    
    public function createDatabase(): DatabaseConnection {
        return new PostgreSQLConnection($this->dbHost);
    }
    
    public function createCache(): CacheProvider {
        return new MemcachedProvider($this->cacheHost);
    }
}

// Service utilisant la factory
class DataService {
    private DatabaseConnection $db;
    private CacheProvider $cache;
    
    public function __construct(DataStackFactory $factory) {
        $this->db = $factory->createDatabase();
        $this->cache = $factory->createCache();
    }
    
    public function getData(string $key): array {
        // Tentative de récupération depuis le cache
        $cached = $this->cache->get($key);
        if ($cached !== null) {
            return ['source' => 'cache', 'data' => $cached];
        }
        
        // Récupération depuis la base de données
        $this->db->connect();
        $result = $this->db->query("SELECT * FROM data WHERE key = '{$key}'");
        $this->db->close();
        
        // Mise en cache
        $this->cache->set($key, json_encode($result));
        
        return ['source' => 'database', 'data' => $result];
    }
}

// Interfaces des produits abstraits
interface PaymentGateway {
    boolean processPayment(double amount, String currency);
    String getTransactionId();
}

interface NotificationService {
    boolean sendConfirmation(String recipient, String transactionId);
    boolean sendReceipt(String recipient, double amount);
}

// Famille PayPal
class PayPalGateway implements PaymentGateway {
    private String transactionId;
    
    @Override
    public boolean processPayment(double amount, String currency) {
        this.transactionId = "PP_" + System.currentTimeMillis();
        System.out.println("💳 Traitement PayPal: " + amount + " " + currency);
        System.out.println("🆔 Transaction ID: " + transactionId);
        return true;
    }
    
    @Override
    public String getTransactionId() {
        return transactionId;
    }
}

class PayPalNotificationService implements NotificationService {
    @Override
    public boolean sendConfirmation(String recipient, String transactionId) {
        System.out.println("📧 PayPal: Confirmation envoyée à " + recipient);
        System.out.println("🆔 Référence: " + transactionId);
        return true;
    }
    
    @Override
    public boolean sendReceipt(String recipient, double amount) {
        System.out.println("🧾 PayPal: Reçu envoyé à " + recipient + " pour " + amount);
        return true;
    }
}

// Abstract Factory
interface PaymentSystemFactory {
    PaymentGateway createPaymentGateway();
    NotificationService createNotificationService();
}

// Concrete Factories
class PayPalSystemFactory implements PaymentSystemFactory {
    @Override
    public PaymentGateway createPaymentGateway() {
        return new PayPalGateway();
    }
    
    @Override
    public NotificationService createNotificationService() {
        return new PayPalNotificationService();
    }
}

class StripeSystemFactory implements PaymentSystemFactory {
    @Override
    public PaymentGateway createPaymentGateway() {
        return new StripeGateway();
    }
    
    @Override
    public NotificationService createNotificationService() {
        return new StripeNotificationService();
    }
}

// Service de paiement utilisant la factory
class PaymentProcessor {
    private PaymentGateway gateway;
    private NotificationService notificationService;
    
    public PaymentProcessor(PaymentSystemFactory factory) {
        this.gateway = factory.createPaymentGateway();
        this.notificationService = factory.createNotificationService();
    }
    
    public boolean processOrder(double amount, String currency, String customerEmail) {
        System.out.println("🛒 Traitement commande: " + amount + " " + currency);
        
        // Traitement du paiement
        boolean paymentSuccess = gateway.processPayment(amount, currency);
        
        if (paymentSuccess) {
            String transactionId = gateway.getTransactionId();
            
            // Envoi des notifications
            notificationService.sendConfirmation(customerEmail, transactionId);
            notificationService.sendReceipt(customerEmail, amount);
            
            System.out.println("✅ Commande traitée avec succès");
            return true;
        } else {
            System.out.println("❌ Échec du traitement");
            return false;
        }
    }
}

// Factory Provider avec enum
enum PaymentProvider {
    PAYPAL, STRIPE
}

class PaymentSystemFactoryProvider {
    public static PaymentSystemFactory getFactory(PaymentProvider provider) {
        switch (provider) {
            case PAYPAL:
                return new PayPalSystemFactory();
            case STRIPE:
                return new StripeSystemFactory();
            default:
                throw new IllegalArgumentException("Fournisseur non supporté: " + provider);
        }
    }
}

⚖️ Avantages et Inconvénients

✅ Avantages

  • Cohérence : Garantit que les produits d'une famille sont compatibles
  • Isolation : Sépare le code client des classes concrètes
  • Échange facile : Permet de changer de famille de produits facilement
  • Principe Ouvert/Fermé : Facile d'ajouter de nouvelles familles
  • Single Responsibility : Chaque factory a une responsabilité claire

❌ Inconvénients

  • Complexité : Beaucoup d'interfaces et de classes
  • Rigidité : Difficile d'ajouter de nouveaux types de produits
  • Over-engineering : Peut être excessif pour des cas simples
  • Maintenance : Hiérarchies parallèles à maintenir
  • Performance : Indirection supplémentaire

🎯 Cas d'Usage Appropriés

✅ Quand l'utiliser

  • Multi-plateforme : Interfaces utilisateur adaptées par OS
  • Thèmes : Familles de composants visuels cohérents
  • Environnements : Dev/Test/Prod avec stacks différentes
  • Drivers : Familles de composants pour différents fournisseurs
  • Formats : Parsers et writers pour différents formats

❌ Quand l'éviter

  • Produit unique : Quand il n'y a qu'un seul type de produit
  • Familles stables : Pas d'évolution prévue des familles
  • Performance critique : L'indirection peut être problématique
  • Prototypage : Développement rapide sans architecture
  • Équipe junior : Complexité non justifiée

🔄 Alternatives et Patterns Liés

🏭 Factory Method

Pour créer un seul type de produit avec des variantes

// Un seul produit, plusieurs implémentations Creator.createProduct() // Retourne différents ConcreteProduct

🔨 Builder Pattern

Pour construire des objets complexes étape par étape

new ProductBuilder().setPart1().setPart2().build()

🧬 Prototype Pattern

Pour créer des objets par clonage d'un prototype

prototypeRegistry.get("type").clone()

🧩 Biais Cognitifs Associés

🏗️ Biais de Sur-Architecture

Manifestation : "Préparons toutes les familles de produits possibles dès maintenant."

Risque : Créer des abstractions complexes pour des besoins hypothétiques, violant le principe YAGNI.

🔨 Marteau de Maslow

Manifestation : "Abstract Factory résout tous les problèmes de création d'objets liés."

Risque : Utilisation systématique même quand Factory Method ou Simple Factory suffiraient.

🎯 Biais de Perfectionnisme

Manifestation : "Il faut que toutes les familles soient parfaitement symétriques et complètes."

Risque : Forcer la création de produits inutiles pour maintenir la symétrie des interfaces.

⚠️ Anti-Patterns à Éviter

🏭 Factory Explosion

Créer trop de factories pour des familles qui ne sont pas vraiment liées.

// ❌ Mauvais : Factories non cohérentes interface MixedFactory { createButton(): Button; createDatabase(): Database; // Pas de lien logique }

🌳 Abstract Overuse

Utiliser Abstract Factory pour des cas simples où Factory Method suffirait.

// ❌ Complexité excessive pour un seul produit interface SingleProductFactory { createOnlyProduct(): Product; // Une seule méthode }
