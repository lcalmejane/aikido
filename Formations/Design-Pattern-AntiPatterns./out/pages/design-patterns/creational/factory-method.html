🏭 Factory Method Pattern

Créer des objets sans spécifier leurs classes concrètes

🎨 Design Patterns
⭐ Difficulté: Moyen
⏱️ 20 min
🏭 Création

🎯 Définition

Le Factory Method est un pattern de création qui fournit une interface pour créer des objets dans une superclasse, mais permet aux sous-classes de modifier le type d'objets qui seront créés.

❌ Problème Résolu

  • Éviter le couplage fort avec des classes concrètes
  • Permettre l'extension sans modification du code existant
  • Centraliser la logique de création d'objets
  • Gérer des familles d'objets similaires

✅ Solution Apportée

  • Interface commune pour la création
  • Délégation aux sous-classes
  • Respect du principe Ouvert/Fermé
  • Flexibilité dans l'instanciation
💡 Principe clé : "Créer des objets sans spécifier leurs classes exactes, en déléguant cette responsabilité aux sous-classes."

🏗️ Structure UML

Creator
+ someOperation(): void
+ factoryMethod(): Product
ConcreteCreator
+ factoryMethod(): ConcreteProduct
Product
+ operation(): void
ConcreteProduct
+ operation(): void

Éléments Clés

  • Creator : Classe abstraite définissant la factory method
  • ConcreteCreator : Implémente la factory method pour créer des produits spécifiques
  • Product : Interface commune des objets créés
  • ConcreteProduct : Implémentation concrète du produit

💡 Point clé : Le client travaille avec l'abstraction Creator, sans connaître les classes concrètes des produits créés.

💻 Implémentations

Exemple : Système de Notifications

// Interface Product
interface Notification {
    send(message: string, recipient: string): boolean;
}

// Produits concrets
class EmailNotification implements Notification {
    send(message: string, recipient: string): boolean {
        console.log(`📧 Email envoyé à ${recipient}: ${message}`);
        // Logique d'envoi d'email
        return true;
    }
}

class SMSNotification implements Notification {
    send(message: string, recipient: string): boolean {
        console.log(`📱 SMS envoyé à ${recipient}: ${message}`);
        // Logique d'envoi de SMS
        return true;
    }
}

class PushNotification implements Notification {
    send(message: string, recipient: string): boolean {
        console.log(`🔔 Push envoyée à ${recipient}: ${message}`);
        // Logique d'envoi de notification push
        return true;
    }
}

// Creator abstrait
abstract class NotificationCreator {
    // Template method utilisant la factory method
    public notifyUser(message: string, recipient: string): boolean {
        const notification = this.createNotification();
        return notification.send(message, recipient);
    }
    
    // Factory method - à implémenter par les sous-classes
    protected abstract createNotification(): Notification;
}

// Creators concrets
class EmailNotificationCreator extends NotificationCreator {
    protected createNotification(): Notification {
        return new EmailNotification();
    }
}

class SMSNotificationCreator extends NotificationCreator {
    protected createNotification(): Notification {
        return new SMSNotification();
    }
}

class PushNotificationCreator extends NotificationCreator {
    protected createNotification(): Notification {
        return new PushNotification();
    }
}

// Utilisation
const emailCreator = new EmailNotificationCreator();
const smsCreator = new SMSNotificationCreator();
const pushCreator = new PushNotificationCreator();

emailCreator.notifyUser("Bienvenue !", "user@example.com");
smsCreator.notifyUser("Code de vérification: 123456", "+33123456789");
pushCreator.notifyUser("Nouvelle mise à jour disponible", "user123");

Version avec Paramètres

// Factory method avec paramètres
class NotificationFactory {
    public static createNotification(type: string): Notification {
        switch (type.toLowerCase()) {
            case 'email':
                return new EmailNotification();
            case 'sms':
                return new SMSNotification();
            case 'push':
                return new PushNotification();
            default:
                throw new Error(`Type de notification non supporté: ${type}`);
        }
    }
}

// Service utilisant la factory
class NotificationService {
    public sendNotification(type: string, message: string, recipient: string): boolean {
        try {
            const notification = NotificationFactory.createNotification(type);
            return notification.send(message, recipient);
        } catch (error) {
            console.error('Erreur lors de l\'envoi:', error.message);
            return false;
        }
    }
}

// Utilisation simplifiée
const service = new NotificationService();
service.sendNotification('email', 'Hello World!', 'test@example.com');
service.sendNotification('sms', 'Code: 456789', '+33987654321');

// Interface Product
interface PaymentProcessor {
    public function processPayment(float $amount, array $details): bool;
}

// Produits concrets
class CreditCardProcessor implements PaymentProcessor {
    public function processPayment(float $amount, array $details): bool {
        echo "💳 Traitement paiement carte: {$amount}€\n";
        // Logique de traitement carte de crédit
        return true;
    }
}

class PayPalProcessor implements PaymentProcessor {
    public function processPayment(float $amount, array $details): bool {
        echo "🅿️ Traitement PayPal: {$amount}€\n";
        // Logique de traitement PayPal
        return true;
    }
}

class BankTransferProcessor implements PaymentProcessor {
    public function processPayment(float $amount, array $details): bool {
        echo "🏦 Traitement virement: {$amount}€\n";
        // Logique de virement bancaire
        return true;
    }
}

// Creator abstrait
abstract class PaymentCreator {
    // Template method
    public function processOrder(float $amount, array $details): bool {
        $processor = $this->createProcessor();
        
        // Logique commune avant traitement
        echo "Validation du montant: {$amount}€\n";
        
        $result = $processor->processPayment($amount, $details);
        
        // Logique commune après traitement
        if ($result) {
            echo "✅ Paiement confirmé\n";
        } else {
            echo "❌ Échec du paiement\n";
        }
        
        return $result;
    }
    
    // Factory method
    protected abstract function createProcessor(): PaymentProcessor;
}

// Creators concrets
class CreditCardCreator extends PaymentCreator {
    protected function createProcessor(): PaymentProcessor {
        return new CreditCardProcessor();
    }
}

class PayPalCreator extends PaymentCreator {
    protected function createProcessor(): PaymentProcessor {
        return new PayPalProcessor();
    }
}

class BankTransferCreator extends PaymentCreator {
    protected function createProcessor(): PaymentProcessor {
        return new BankTransferProcessor();
    }
}

// Utilisation
$creditCardCreator = new CreditCardCreator();
$paypalCreator = new PayPalCreator();
$bankCreator = new BankTransferCreator();

$creditCardCreator->processOrder(99.99, ['card' => '****1234']);
$paypalCreator->processOrder(149.50, ['email' => 'user@example.com']);
$bankCreator->processOrder(299.00, ['iban' => 'FR76****']);

// Interface Product
interface Document {
    void open();
    void save();
    void close();
}

// Produits concrets
class WordDocument implements Document {
    private String filename;
    
    public WordDocument(String filename) {
        this.filename = filename;
    }
    
    @Override
    public void open() {
        System.out.println("📄 Ouverture document Word: " + filename);
    }
    
    @Override
    public void save() {
        System.out.println("💾 Sauvegarde document Word: " + filename);
    }
    
    @Override
    public void close() {
        System.out.println("❌ Fermeture document Word: " + filename);
    }
}

class PDFDocument implements Document {
    private String filename;
    
    public PDFDocument(String filename) {
        this.filename = filename;
    }
    
    @Override
    public void open() {
        System.out.println("📋 Ouverture PDF: " + filename);
    }
    
    @Override
    public void save() {
        System.out.println("💾 Sauvegarde PDF: " + filename);
    }
    
    @Override
    public void close() {
        System.out.println("❌ Fermeture PDF: " + filename);
    }
}

// Creator abstrait
abstract class Application {
    // Template method
    public void createDocument(String filename) {
        Document doc = createDocumentInstance(filename);
        doc.open();
        // Logique commune de traitement
        System.out.println("⚙️ Traitement du document...");
        doc.save();
    }
    
    // Factory method
    protected abstract Document createDocumentInstance(String filename);
}

// Creators concrets
class WordApplication extends Application {
    @Override
    protected Document createDocumentInstance(String filename) {
        return new WordDocument(filename);
    }
}

class PDFApplication extends Application {
    @Override
    protected Document createDocumentInstance(String filename) {
        return new PDFDocument(filename);
    }
}

// Factory avec enum pour plus de robustesse
enum DocumentType {
    WORD, PDF
}

class DocumentFactory {
    public static Document createDocument(DocumentType type, String filename) {
        switch (type) {
            case WORD:
                return new WordDocument(filename);
            case PDF:
                return new PDFDocument(filename);
            default:
                throw new IllegalArgumentException("Type de document non supporté: " + type);
        }
    }
}

// Utilisation
public class Main {
    public static void main(String[] args) {
        // Utilisation avec héritage
        Application wordApp = new WordApplication();
        Application pdfApp = new PDFApplication();
        
        wordApp.createDocument("rapport.docx");
        pdfApp.createDocument("facture.pdf");
        
        // Utilisation avec factory statique
        Document doc1 = DocumentFactory.createDocument(DocumentType.WORD, "memo.docx");
        Document doc2 = DocumentFactory.createDocument(DocumentType.PDF, "guide.pdf");
        
        doc1.open();
        doc2.open();
    }
}

⚖️ Avantages et Inconvénients

✅ Avantages

  • Découplage : Évite le couplage entre créateur et produits concrets
  • Extensibilité : Facile d'ajouter de nouveaux types de produits
  • Principe Ouvert/Fermé : Extension sans modification
  • Single Responsibility : Sépare la création de l'utilisation
  • Polymorphisme : Utilisation uniforme des produits

❌ Inconvénients

  • Complexité : Plus de classes et d'interfaces
  • Hiérarchie parallèle : Creators et Products doivent évoluer ensemble
  • Over-engineering : Peut être excessif pour des cas simples
  • Indirection : Plus difficile à suivre le flux d'exécution
  • Maintenance : Plus de code à maintenir

🎯 Cas d'Usage Appropriés

✅ Quand l'utiliser

  • Frameworks : Permettre aux utilisateurs d'étendre les fonctionnalités
  • Bibliothèques : Créer des objets sans connaître leurs types exacts
  • Plugins : Système extensible de composants
  • Parsers : Différents formats de fichiers
  • Drivers : Différents types de bases de données

❌ Quand l'éviter

  • Cas simples : Quand un seul type d'objet est créé
  • Prototypes : Développement rapide sans extensibilité
  • Performance critique : L'indirection peut impacter les performances
  • Équipe junior : Complexité supplémentaire non justifiée
  • Requirements fixes : Pas d'évolution prévue

🔄 Alternatives et Patterns Liés

Pour créer des objets par clonage

🧩 Biais Cognitifs Associés

🔨 Marteau de Maslow

Manifestation : "Factory Method résout tous les problèmes de création d'objets."

Risque : Utilisation systématique même pour des cas simples où une instanciation directe suffirait.

🏗️ Biais de Complexité

Manifestation : "Plus c'est complexe, plus c'est professionnel et maintenable."

Risque : Over-engineering avec des hiérarchies inutiles pour des besoins simples.

📈 Biais de Prématurité

Manifestation : "Préparons-nous à toutes les extensions futures possibles."

Risque : Créer une architecture complexe pour des besoins hypothétiques (YAGNI violation).

⚠️ Anti-Patterns à Éviter

🏭 Factory Overuse

Utiliser Factory Method même pour des créations simples et uniques.

// ❌ Mauvais : Factory pour un seul type class StringFactory { createString(value) { return new String(value); } }

🌳 Deep Hierarchy

Créer des hiérarchies trop profondes de creators et products.

// ❌ Hiérarchie excessive AbstractCreator → BaseCreator → SpecializedCreator → ConcreteCreator
