📋 Copy-Paste Programming

L'anti-pattern de la duplication de code par copier-coller

🦨 Code Smells
⏱️ ~25 minutes
🎯 Refactoring urgent
🧩 3 biais cognitifs liés

🎯 Définition

Le Copy-Paste Programming est un anti-pattern où les développeurs dupliquent du code existant en le copiant-collant plutôt que de créer des abstractions réutilisables. Cette pratique crée une dette technique massive et rend la maintenance extrêmement difficile.

❌ Problèmes Causés

  • Duplication massive de code identique
  • Bugs qui se propagent dans toutes les copies
  • Maintenance cauchemardesque (N modifications pour 1 changement)
  • Taille du codebase qui explose inutilement
  • Incohérences entre les différentes versions

✅ Solutions Apportées

  • Extraction de méthodes communes
  • Création de classes utilitaires
  • Utilisation de l'héritage et composition
  • Patterns Template Method et Strategy
  • Bibliothèques et modules réutilisables
⚠️ Règle des 3 : Si vous copiez le même code 3 fois, il est temps de créer une abstraction. "Three strikes and you refactor!"

Caractéristiques du Copy-Paste Programming

📋
Code dupliqué

Blocs identiques ou quasi-identiques répétés

🔄
Modifications multiples

Même changement à faire en N endroits

🐛
Bugs en cascade

Erreur qui se propage dans toutes les copies

📈
Croissance exponentielle

Taille du code qui explose rapidement

🧠 Biais Cognitifs Associés

Le Copy-Paste Programming résulte de biais cognitifs qui privilégient la solution immédiate :

⚡

Biais de Disponibilité

Manifestation : "J'ai déjà ce code qui marche, je le copie !"

La tendance à utiliser la solution la plus immédiatement disponible (le code existant) plutôt que de réfléchir à une abstraction.

Exemple : Copier une fonction de validation d'email plutôt que de créer une classe Validator réutilisable.
⏰

Biais de Pression Temporelle

Manifestation : "Pas le temps de refactorer, je copie vite fait !"

La pression des délais pousse à prendre le raccourci du copier-coller sans considérer les conséquences à long terme.

Exemple : Dupliquer une fonction de calcul de prix plutôt que de la paramétrer correctement.
🎯

Biais d'Optimisme

Manifestation : "C'est juste pour cette fois, je refactorerai plus tard !"

Sous-estimation systématique du coût futur de maintenance et surestimation de la probabilité de refactorer "plus tard".

Exemple : "Je duplique ce service, mais je créerai une classe abstraite dans le prochain sprint."

    public void generateSalesReport(Date startDate, Date endDate, String format) {
        // Validation des paramètres
        if (startDate == null || endDate == null) {
            throw new IllegalArgumentException("Start and end dates are required");
        }
        if (startDate.after(endDate)) {
            throw new IllegalArgumentException("Start date must be before end date");
        }
        if (format == null || format.isEmpty()) {
            format = "PDF";
        }
        
        // Récupération des données
        List sales = salesRepository.findByDateRange(startDate, endDate);

        double totalAmount = 0;
        int totalTransactions = sales.size();
        Map salesByProduct = new HashMap<>();
        
        for (Sale sale : sales) {
            totalAmount += sale.getAmount();
            String productName = sale.getProduct().getName();
            salesByProduct.put(productName, 
                salesByProduct.getOrDefault(productName, 0.0) + sale.getAmount());
        }
        
        double averageTransaction = totalTransactions > 0 ? totalAmount / totalTransactions : 0;
        
        // Génération du rapport
        ReportData reportData = new ReportData();
        reportData.setTitle("Sales Report");
        reportData.setStartDate(startDate);
        reportData.setEndDate(endDate);
        reportData.setTotalAmount(totalAmount);
        reportData.setTotalTransactions(totalTransactions);

// 2. Factory pour créer différents types d'utilisateurs
class UserFactory {
    private UserValidator $validator;
    private DatabaseInterface $db;
    private LoggerInterface $logger;
    private EmailServiceInterface $emailService;
    
    public function __construct(
        UserValidator $validator,
        DatabaseInterface $db,
        LoggerInterface $logger,
        EmailServiceInterface $emailService
    ) {
        $this->validator = $validator;
        $this->db = $db;
        $this->logger = $logger;
        $this->emailService = $emailService;
    }
    
    public function createUser(array $data, UserType $userType): int {
        // 1. Validation commune
        $this->validator->validateBasicData($data);
        $this->validator->validateEmailUniqueness($data['email'], $this->db);
        
        // 2. Validation spécifique au type
        $userType->validateSpecificData($data);
        
        // 3. Préparation des données
        $userData = $this->prepareUserData($data, $userType);
        
        // 4. Création en base
        $userId = $this->insertUser($userData);
        
        // 5. Actions post-création
        $this->performPostCreationActions($userId, $data, $userType);
        
        return $userId;
    }
    
    private function prepareUserData(array $data, UserType $userType): array {
        $userData = [
            'email' => $data['email'],
            'password' => password_hash($data['password'], PASSWORD_BCRYPT),
            'name' => $data['name'],
            'type' => $userType->getTypeName(),
            'created_at' => date('Y-m-d H:i:s')
        ];
        
        // Ajout des champs spécifiques au type
        return array_merge($userData, $userType->getSpecificFields($data));
    }
    
    private function insertUser(array $userData): int {
        $fields = implode(', ', array_keys($userData));
        $placeholders = str_repeat('?,', count($userData) - 1) . '?';
        $sql = "INSERT INTO users ({$fields}) VALUES ({$placeholders})";
        
        return $this->db->insert($sql, array_values($userData));
    }
    
    private function performPostCreationActions(int $userId, array $data, UserType $userType): void {
        // Log
        $this->logger->info($userType->getLogMessage(), [
            'user_id' => $userId,
            'email' => $data['email']
        ]);
        
        // Email de bienvenue
        $userType->sendWelcomeEmail($this->emailService, $data['email'], $data['name'], $data);
    }
}

// 1. Classe abstraite définissant le template de génération de rapport
public abstract class AbstractReportGenerator {
    
    protected final Logger logger = LoggerFactory.getLogger(getClass());
    
    @Autowired
    protected NotificationService notificationService;
    
    @Autowired
    protected ReportExportService exportService;
    
    // Template method - définit l'algorithme général
    public final void generateReport(Date startDate, Date endDate, String format) {
        // 1. Validation commune
        validateParameters(startDate, endDate, format);
        
        // 2. Récupération des données (spécifique à chaque type)
        List data = fetchData(startDate, endDate);
        
        // 3. Calculs statistiques (spécifique à chaque type)
        ReportStatistics stats = calculateStatistics(data);
        
        // 4. Génération du rapport (commune)
        ReportData reportData = buildReportData(stats, startDate, endDate);
        
        // 5. Export (commun)
        exportReport(reportData, format);
        
        // 6. Log et notification (communs)
        logReportGeneration(startDate, endDate);
        notifyReportReady(format);
    }
    
    // Méthodes communes (implémentation finale)
    private void validateParameters(Date startDate, Date endDate, String format) {
        if (startDate == null || endDate == null) {
            throw new IllegalArgumentException("Start and end dates are required");
        }
        if (startDate.after(endDate)) {
            throw new IllegalArgumentException("Start date must be before end date");
        }
    }
    
    private ReportData buildReportData(ReportStatistics stats, Date startDate, Date endDate) {
        ReportData reportData = new ReportData();
        reportData.setTitle(getReportTitle());
        reportData.setStartDate(startDate);
        reportData.setEndDate(endDate);
        reportData.setTotalAmount(stats.getTotalAmount());
        reportData.setTotalTransactions(stats.getTotalCount());
        reportData.setAverageTransaction(stats.getAverage());
        reportData.setDetailsByCategory(stats.getCategoryBreakdown());
        return reportData;
    }
    
    private void exportReport(ReportData reportData, String format) {
        String filename = getReportFilename();
        exportService.export(reportData, format, filename);
    }
    
    private void logReportGeneration(Date startDate, Date endDate) {
        logger.info("{} generated for period {} to {}", getReportTitle(), startDate, endDate);
    }
    
    private void notifyReportReady(String format) {
        notificationService.notifyReportReady(getReportType(), format);
    }
    
    // Méthodes abstraites (à implémenter par les sous-classes)
    protected abstract List fetchData(Date startDate, Date endDate);
    protected abstract ReportStatistics calculateStatistics(List data);
    protected abstract String getReportTitle();
    protected abstract String getReportType();
    protected abstract String getReportFilename();
}

@Service
public class SalesReportGenerator extends AbstractReportGenerator {
    
    @Autowired
    private SalesRepository salesRepository;
    
    @Override
    protected List fetchData(Date startDate, Date endDate) {
        return salesRepository.findByDateRange(startDate, endDate);
    }
    
    @Override
    protected ReportStatistics calculateStatistics(List sales) {
        double totalAmount = sales.stream()
            .mapToDouble(Sale::getAmount)
            .sum();
        
        int totalCount = sales.size();
        double average = totalCount > 0 ? totalAmount / totalCount : 0;
        
        Map categoryBreakdown = sales.stream()
            .collect(Collectors.groupingBy(
                sale -> sale.getProduct().getName(),
                Collectors.summingDouble(Sale::getAmount)
            ));
        
        return new ReportStatistics(totalAmount, totalCount, average, categoryBreakdown);
    }
    
    @Override
    protected String getReportTitle() {
        return "Sales Report";
    }
    
    @Override
    protected String getReportType() {
        return "sales_report";
    }
    
    @Override
    protected String getReportFilename() {
        return "sales_report";
    }
}

    @Override
    protected String getReportFilename() {
        return "financial_report";
    }
}

// 3. Service principal utilisant une Factory
@Service
public class ReportService {
    
    private final Map> generators;
    
    public ReportService(List> generatorList) {
        this.generators = generatorList.stream()
            .collect(Collectors.toMap(
                AbstractReportGenerator::getReportType,
                Function.identity()
            ));
    }
    
    public void generateReport(String reportType, Date startDate, Date endDate, String format) {
        AbstractReportGenerator generator = generators.get(reportType);
        
        if (generator == null) {
            throw new IllegalArgumentException("Unknown report type: " + reportType);
        }
        
        generator.generateReport(startDate, endDate, format);
    }
}

@Service
public class ReportExportService {
    
    @Autowired
    private PdfGenerator pdfGenerator;
    
    @Autowired
    private ExcelGenerator excelGenerator;
    
    @Autowired
    private CsvGenerator csvGenerator;
    
    public void export(ReportData reportData, String format, String filename) {
        switch (format.toUpperCase()) {
            case "PDF":
                pdfGenerator.generateReport(reportData, filename + ".pdf");
                break;
            case "EXCEL":
                excelGenerator.generateReport(reportData, filename + ".xlsx");
                break;
            case "CSV":
                csvGenerator.generateReport(reportData, filename + ".csv");
                break;
            default:
                throw new IllegalArgumentException("Unsupported format: " + format);
        }
    }
}

📊 Métriques et Détection

📋 Duplication de Code

DRY > 5%

Pourcentage de code dupliqué dans le projet

Seuils :
  • < 3% : Acceptable
  • 3-5% : À surveiller
  • > 5% : Action requise

🔍 Similarité de Code

Similarity > 80%

Pourcentage de similarité entre blocs de code

Détection :
  • Blocs > 6 lignes identiques
  • Fonctions avec même structure
  • Patterns répétitifs

📏 Taille des Méthodes

LOC Variance

Variance de taille entre méthodes similaires

Indicateurs :
  • Méthodes de même nom
  • Tailles très différentes
  • Évolution divergente

🔄 Fréquence de Modification

Change Frequency

Nombre de fichiers modifiés ensemble

Signaux :
  • Commits touchant N fichiers
  • Même bug fixé partout
  • Changements synchronisés
